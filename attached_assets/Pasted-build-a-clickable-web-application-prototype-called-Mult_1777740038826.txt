build a clickable web application prototype called Multaqa  — 

a coworking space seat and room booking platform. Users come to browse available desks and rooms, choose one, and book it in advance so their spot is guaranteed when they arrive.

═══════════════════════════════════════════════════════════

PRODUCT CONTEXT

═══════════════════════════════════════════════════════════

Product name: Multaqa 

Tagline: Your seat. Secured.

Platform: Responsive web application (desktop-first, mobile-friendly)

Language: English (Arabic support planned for a later phase)

The core problem: Remote workers, freelancers, and students in Palestine 

have no digital way to see real-time seat availability or book a workspace 

in advance. They walk in to find spaces full, book via WhatsApp with no 

confirmation, or give up entirely. Maqarr solves this by letting users 

browse, choose, and confirm their exact seat or room before they leave home.

Target users:

- Remote workers and freelancers (primary) — need reliable WiFi, quiet 

  zones, advance booking, price transparency

- Students — need affordable day passes, quiet study environment

- Small teams — need meeting rooms or adjacent desks booked together

- Space admin (internal) — manages all bookings, availability, and 

  unpaid cash reservations across both locations

VISUAL STYLE & DESIGN SYSTEM

═══════════════════════════════════════════════════════════

Style: Clean, modern, professional, trustworthy. Bold and energetic without being aggressive. Think a well-designed SaaS product with strong brand presence — confident use of color, generous whitespace, clear hierarchy.

Color palette (use same color codes provided but feel free to adjust where to use them where needed and for better result):

Primary #FF5100 (used for all primary 

buttons, active states, key CTAs, links, and highlights)

Dark / Navy: #001279 (deep navy blue — used for navigation background, 

headings, sidebar, dark section backgrounds, and text on light surfaces, CTA color)

Mid / Secondary text: #535060 (muted dark gray-purple — used for body 

text, secondary labels, descriptions, placeholder text, and 

less prominent UI elements)

White: #FFFFFF (main page background, card backgrounds, 

input field backgrounds)

 Derived supporting colors (generate from the palette above):

- Light orange tint: #FFF1EB (very light #FF5100 tint — 

  used for card hover states, selected states, subtle backgrounds)

- Light navy tint: #E8EBFF (very light #001279 tint — 

  used for info banners, admin section backgrounds, 

  secondary card fills)

- Border color: #E0E0E0 (neutral light gray for card borders, 

  dividers, input borders)

- Success green: #1A7A4A (used only for "Available" status 

  badges and confirmed payment states — 

  not part of main palette but needed functionally)

- Error red: #CC1A00 (used only for overdue/unpaid alerts, 

  error messages, and unavailable states — 

  a darker shade of the primary to signal urgency)

Typography: Clean sans-serif. Use Inter or a similar modern font.

Navigation and headings use #001279 (navy).

Body text uses #535060 (mid gray).

CTA buttons use #FF5100 background with #FFFFFF text.

Secondary buttons use #001279 background with #FFFFFF text 

or #001279 border with #001279 text on white background.

Rounded corners on cards and buttons (8px radius). 

Subtle box shadows. Generous whitespace. No clutter.

Seat color coding (used on floor plan and seat cards):

- Blue (#001279 background, white text) = Deep Work / No Talking zone

- Orange (#FF5100 background, white text) = Calls / Zoom Allowed zone

- Red (#CC1A00) = Unavailable / Reserved / Under Maintenance

- Green (#1A7A4A) = Available

USER ROLES

═══════════════════════════════════════════════════════════

Role 1: Guest User (not logged in)

- Can browse all desks and rooms

- Can view desk and room details

- Can complete a full booking by entering email only — NO registration 

  required. Guest checkout is a core feature.

- Receives booking confirmation via email

- Cannot access My Reservations dashboard (managed via email link only)

Role 2: Registered User (logged in)

- All guest capabilities plus:

- Access to My Reservations dashboard

- Can modify or cancel bookings

- Can download booking receipts

- Can choose to hide identity from "Who's in the Space Today" board 

  (anonymous booking toggle)

Role 3: Admin (logged in with admin role)

- Separate admin dashboard

- View and manage all bookings across both locations

- Block seats for maintenance

- Create or cancel bookings on behalf of users

- Mark cash bookings as paid

- View unpaid cash bookings list with deadlines

- Control role-based access (e.g., mark rooms as admin-only)

MAIN CLICKABLE FLOWS TO CONNECT

═══════════════════════════════════════════════════════════

Connect all screens with working click interactions 

for the following flows:

Flow 1 — Guest Desk Booking (most important flow):

Homepage → click "Browse Desks" → Desk Browsing Page → 

click "View Details" on any available desk → Desk Detail Page → 

click "Book This Desk" → Booking Flow Step 1 (date + time) → 

click "Continue" → Booking Flow Step 2 (review + email entry) → 

click "Confirm Booking" → Booking Confirmation Screen

Flow 2 — Room Booking:

Homepage → click "Browse Rooms" → Room Browsing Page → 

click "View Details" → Room Detail Page → 

click "Book This Room" → Booking Flow Step 1 → 

click "Continue" → Booking Flow Step 2 → 

click "Confirm Booking" → Booking Confirmation Screen

Flow 3 — Registered User manages reservations:

Login Page → log in → My Reservations Dashboard → 

click "Modify" on a booking → Modify Booking Flow → 

confirm change → back to My Reservations Dashboard

Flow 4 — Admin manages unpaid cash bookings:

Admin Dashboard Overview → click "Unpaid Cash Bookings" → 

Unpaid Cash Bookings Screen → click "Mark as Paid" → 

booking status updates to Paid → removed from unpaid list

Flow 5 — Admin blocks a seat:

Admin Dashboard → click "Seat Management" → 

Seat Management Screen → click "Block for Maintenance" 

on a desk → desk status changes to "Maintenance" → 

desk shows as unavailable on the user-facing Desk Browsing Page

Flow 6 — Login and view reservations:

Homepage → click "Log In" → Login Page → 

enter credentials → My Reservations Dashboard → 

click on a booking → see full booking details

KEY BEHAVIORS & INTERACTIONS

═══════════════════════════════════════════════════════════

1. Real-time availability simulation: When a desk is clicked 

   and booked in the prototype, its status on the browsing page 

   should reflect "Reserved." If full simulation is not possible, 

   show desks in mixed states (some available, some reserved) 

   to demonstrate the concept visually.

2. Location toggle: When switching between Nablus and Ramallah 

   on any browsing page, the content refreshes to show that 

   location's desks and rooms. Use different placeholder data 

   for each location.

3. Same-day time slot filtering: On the date picker, if today 

   is selected, only future time slots are shown. Past slots 

   are greyed out and not clickable. Each available slot shows 

   remaining hours until closing 

   (e.g., "3 hours left before closing").

4. Guest checkout: On Booking Flow Step 2, if the user is 

   not logged in, the email field is shown and required. 

   If logged in, the email is pre-filled and the field 

   is collapsed or read-only.

5. Cash payment deadline: On the Booking Confirmation Screen 

   and in My Reservations Dashboard, the payment deadline 

   (booking date + 3 days) is always shown in amber/gold 

   color with clear text: "Pay on-site by [date]."

6. Admin-only room: If a room is marked "Admin-Only" in 

   Seat Management, it should not appear on the user-facing 

   Room Browsing Page.

7. Booking reference format: Use the format MQR-XXXXX 

   (e.g., MQR-20491) for all booking reference numbers 

   shown in the prototype.

8. Navigation: 

   - User-facing pages: top navigation bar with 

     Maqarr logo (left), Browse Desks | Browse Rooms 

     links (center), and Log In | Sign Up (right). 

     When logged in: replace Log In/Sign Up with 

     user avatar + "My Bookings" link.

   - Admin pages: left sidebar navigation, 

     no top nav from user-facing site.

9. Responsive: All user-facing screens must look good on 

   mobile (375px width) and desktop (1280px width).

10. Placeholder data to use:

    Desks: Desk A-1 through A-8 at Nablus, Desk B-1 through 

    B-6 at Ramallah. Mix of Flex, Hot, and Dedicated types. 

    Mix of Deep Work and Calls Allowed zones. 

    Prices: 15 ILS/hour, 50 ILS/half-day, 85 ILS/full-day.

    Rooms: "The Focus Room" (capacity 4), "Meeting Room 1" 

    (capacity 8), "The Pod" (capacity 2) at Nablus. 

    Prices: 40 ILS/hour, 140 ILS/half-day.

    Users: Use names like Khalid, Tala, Omar, Sara, Rami 

    as placeholder booking names.

    Locations: 

    Nablus — Building Al-Maseef, Floor 3, Nablus City Center

    Ramallah — Al-Bireh Commercial Center, Floor 2, Ramallah

TONE & FEEL

═══════════════════════════════════════════════════════════

Multaqa should feel trustworthy, local, and professional. 

It is built for Palestinians — it should feel familiar and 

warm, not like a generic global SaaS product. Every label, 

button, and empty state should speak directly to the user 

in plain, friendly language. No jargon. No corporate tone. 

The product should feel like it was made specifically 

for them — because it was.

Primary emotion the user should feel when using it: 

Confidence. "I know my seat is waiting for me."
